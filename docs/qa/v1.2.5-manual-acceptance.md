## Preparation and privacy rules

1. Use a **throwaway VS Code user-data/profile directory** and a fresh synthetic workspace. Do not point LineLoom at a private repository or reuse personal `settings.json`.
2. Obtain only an independently verified 1.2.5 preview candidate VSIX built by the repository CI, or build one from the tested source revision. Confirm extension ID `SanskarCodes.lineloom`, version `1.2.5`, *pre-release channel* metadata and local SHA-256. A CI artifact is **not** a GitHub public release.
3. For the local model cases use a trusted local Ollama loopback endpoint and **synthetic source only**. No remote endpoint consent is required or expected.
   Before opening the editor, optionally run the user-approved CLI smoke check `npm run qa:ollama -- --run --model <installed-tag>` in a disposable development checkout. It sends **only a fixed public example** to a loopback HTTP origin and reports bounded metrics; it must reject broken UTF-8 and blank or unsafe generated text. This automated CLI check is not a substitute for manual editor acceptance and is **NOT RUN against real Ollama** in this report.
4. Never attach real prompts, code, filesystem paths, ignore-rule text, tokens, model responses or sensitive screenshots to public issues. Report only platform/software versions, pass/fail, timings when explicitly opted in, and anonymized reproduction steps.
5. Record separate results for Windows, macOS and Linux; do not infer results from the automated GitHub-hosted runners.

## Important limitations

- Privacy eligibility latency is **not** end-to-end Ollama inference latency. The 64-sample p95 and session summary are aggregates, not path-level metrics.
- No new cross-file repository-context feature is available in 1.2.5. The proposed v1.3.0 contextual work requires its own privacy review.
- GitHub Actions runner success cannot prove actual physical workstation storage timing, UI focus, real model usefulness, or local hardware performance.
- A completion already sent to a server cannot be recalled. Always establish exclusions **before** enabling completions on sensitive files.
