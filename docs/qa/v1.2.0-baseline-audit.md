# LineLoom v1.2.0 — baseline audit and risk register

**Audited from main commit `19526098a86007920e6da27adee3bd6d2213bc64`.**
This records the original state before the v1.2.0 development branch. The
repository and Actions logs are authoritative; this document does not claim a
physical IDE session or actual model benchmark.

## Verified baseline

- Latest existing public stable release: v1.0.0 with `.vsix` and SHA-256;
  v1.1.0 and v1.1.1 were GitHub **pre-releases**.
- MIT, publisher `SanskarCodes`, VS Code ID `SanskarCodes.lineloom`,
  Node/TypeScript extension and Ollama backend.
- Native Tree View sidebar, language/model controls and privacy-safe status,
  active editor language, default/override model, provisional eligibility.
- Nine language IDs with JSX/TSX aliases; experimental Go, Java, C and C++.
- Bounded active-document context extraction, stream limits, FIM only for
  explicitly recognized Qwen 2.5 coder family, conservative completion
  filtering and timed request cancellation.
- Editor trust, ignored/sensitive-file and path/symlink rules, blocked remote
  endpoints unless HTTPS and explicitly approved; no telemetry.
- `main` CI and dependency security were green at the audit snapshot;
  production integration uses a **mock Ollama server**, not a real model.

## Identified gaps and risks

1. Sidebar showed only requests/suggestions/failures, not cached/empty/cancelled
   counts, generation status, typed reuse or opt-in measured latency. This
   obscured failure/no-model diagnostics and reduced support usefulness.
2. Existing `listModels` and model picker commands collapsed diverse network
   and parser errors into generic messages. Safe categorical guidance is
   preferable to showing raw server errors or secret-bearing URLs.
3. Current CI still emitted **pre-release VSIX metadata** on the branch before
   stable preparation; the v1.0.0-only stable workflow cannot be reused.
   A versioned, stable-channel negative pre-release marker check was missing.
4. No verified user-machine Ollama tests, GPU/CPU cold/warm measurements,
   Windows/macOS/Linux hands-on interaction or accessibility acceptance.
5. No observed real upgrade from stable v1.0.0 or preview v1.1.1, and no
   verification of publisher access to update both external registries.
6. C# and Dart are not registered or tested; adding labels only would be
   misleading. Keep these out until integrated/tested end-to-end.
7. The `crossFileContext` compatibility setting is intentionally reserved.
   It must remain inactive and must not trigger workspace-wide reads.

## Targeted implementation phases

1. Keep existing engine/permissions; enhance local sidebar metrics and state.
2. Provide safe Ollama error categorization; add unit/integration coverage.
3. Prepare `1.2.0` manifest/lockfile/tests; make CI produce a **stable**
   VSIX and reject preview marker or risky shipped files.
4. Write release notes, genuine manual QA matrix and a gated, opt-in
   stable publisher that never runs automatically on an ordinary push.
5. Run PR CI on Windows/macOS/Linux, mocked extension host, dependency audit
   and VSIX clean install; merge only if green.
6. **Block public stable release** until physical/manual, model quality,
   privacy and upgrade evidence is recorded in
   [issue #21](https://github.com/sanskarIN/LineLoom/issues/21).

## Performance and security policy

No benchmark numbers are recorded here because none were measured on real
Ollama hardware. Continue bounding inference responses, preserving cancellation,
using only the active document, and never persisting or uploading source content.
Sidebar rendering must not call Ollama or scan filesystem paths.
