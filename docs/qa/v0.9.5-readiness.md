## Manual Windows acceptance test

Use a non-sensitive scratch workspace. Record **test date, VS Code version, LineLoom version, machine OS, Ollama version, model tag and CPU/GPU description**, but **do not post source code, prompts, credentials or private file paths**.

1. [ ] From VS Code Extensions → ··· → **Install from VSIX**, install **LineLoom-0.9.5.vsix**. Confirm installed source is VSIX, extension ID is `sanskarcodes.lineloom`, version is `0.9.5`, and extension is enabled.
2. [ ] Run `ollama list`; confirm the selected coding model is installed. Use **LineLoom: Check Ollama Connection**. Confirm the exact VS Code message reports it available.
3. [ ] In a trusted `.rs` file, run **LineLoom: Trigger Completion** at a suitable cursor. Check that *ghost text appears*, accepts via VS Code's inline-accept command / Tab binding, and the resulting Rust source remains editable.
4. [ ] Repeat manual completion and acceptance with basic `.py`, `.js`, `.ts`, and `.kt` fixtures. Do not claim high quality simply because text appears.
5. [ ] Test **Pause Automatic Suggestions**, then a manual trigger; resume automatic suggestions. Confirm no unexpected background request while paused.
6. [ ] Switch model with **Select Model**; optionally configure a different TypeScript model using **Assign Language Model**. Check both produce a completion only with installed models.
7. [ ] Open a scratch `.env`, an explicitly excluded file, and an untrusted workspace. Ensure completions are denied before any prompt is sent.
8. [ ] Stop Ollama: confirm the connection checker reports it unavailable and the editor remains responsive; restart Ollama and check recovery.
9. [ ] Exercise multiline completion, typing part of a suggestion, stale generation cancelled by cursor moves, and selection/multiple-cursor denial.
10. [ ] Check fully offline inference **only after model and extension are already installed**. Confirm no remote endpoint is configured.
11. [ ] For an approved test endpoint only, verify the explicit remote HTTPS opt-in/approval flow and rejection of unintended redirects (never use production secrets).
12. [ ] Use **LineLoom: Open Diagnostics** and note request count, failure count and observed behavior (no code or prompt contents).

## How to report results

For each test, record **PASS / FAIL / NOT TESTED**, environment and observable result without confidential code. A failure should reference a GitHub issue. Do not label tests as passed based on generated code, synthetic fixtures, GitHub Actions success alone, or an extension-install screenshot that does not demonstrate inference.

### Automated smoke test

The v0.9.5 CI builds a `--pre-release` VSIX, checks its archive contents, then uses `@vscode/test-electron` to download VS Code and run `--install-extension` and `--list-extensions --show-versions` against an isolated temporary extension directory. This confirms package compatibility with VS Code's **headless CLI**; it does **not** test a physical editor UI, actual user keystrokes or Ollama inference.

**Status:** The stable-channel GitHub milestone was subsequently authorized by the maintainer. Any unchecked real-device/model tests still need evidence and should be reported transparently; do not mark them as passed automatically.
