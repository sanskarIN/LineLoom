# LineLoom v1.2.4 — Manual Release Acceptance

**Status: not yet verified on physical Windows, macOS or Linux machines.** This is an executable checklist for human reviewers, not a claim that any of its checks passed. The [v1.2.4 GitHub pre-release](https://github.com/sanskarIN/LineLoom/releases/tag/v1.2.4) passed [automated publisher CI](https://github.com/sanskarIN/LineLoom/actions/runs/39903006652); this document covers what those tests **cannot** establish.

## Ground rules

- Use a **fresh, disposable VS Code profile** and a synthetic workspace, never a private repository or a real credentials file.
- Download `LineLoom-1.2.4.vsix` plus its `LineLoom-1.2.4.sha256` from the [official GitHub release](https://github.com/sanskarIN/LineLoom/releases/tag/v1.2.4). Verify SHA-256 before installing: `05a715f49fe332ec53c63de80f3ebdabedc8a55c07ce2aa8b000c69ddee2ccec`. Prefer your platform's native checksum utility.
- Install using **VS Code → Extensions → … → Install from VSIX…**. Do **not** use the full Visual Studio VSIX Installer, and do not modify a primary VS Code profile. Confirm extension ID `SanskarCodes.lineloom` and preview version `1.2.4`.
- Keep Ollama at its **local loopback endpoint** for acceptance. Any deliberately remote inference experiment requires separate documented review and explicit endpoint approval; it is not needed for the checklist.

## Acceptance matrix

Record **OS + version, VS Code version, Ollama/model version when applicable, workspace depth, storage type, check result, and anonymized notes** in [issue #54](https://github.com/sanskarIN/LineLoom/issues/54). Never paste paths, model prompts, generated code, ignore-rule contents, secrets or user identifiers into issue comments.

| Area | Safe synthetic procedure | Expected result |
| --- | --- | --- |
| Fresh install | Install the published VSIX in a disposable VS Code profile and open its Control Center | Extension registers commands, status and sidebar without startup errors |
| Default privacy | With `lineloom.performanceDiagnostics` unset, run a few eligible and ineligible completion requests, then open **LineLoom: Open Diagnostics** | No privacy eligibility latency summary is displayed by default |
| Opt-in metrics | Set `lineloom.performanceDiagnostics` to true in the disposable profile; trigger allowed and blocked requests using synthetic files | Only aggregate counts and last/average/recent-p95/session-max policy-check milliseconds appear |
| Opt-out erasure | Toggle the preference back to false while a synthetic request is processing, then reopen Diagnostics | Privacy timing summary is hidden and cleared; late requests cannot repopulate disabled statistics |
| Ignore rules | Put synthetic source in `private/demo.ts`, add `private/` to a local root or nested `.gitignore` or `.lineloomignore`, and attempt a completion | No model generation request is made for an ignored file |
| Live rules | Begin with a synthetic permitted file, then edit, create or delete a matching ignore source and retry; also test same-length rewrites | Subsequent checks use current privacy rules and fail closed on unreadable/racing sources; no previously excluded text is sent |
| Deep workspaces | Repeat the synthetic ignore-rule check across shallow and nested directories (up to documented 24-scope limit) | No privacy bypass or unexpected exception; excessive depth is denied |
| Storage variation | Compare safe synthetic local SSD and, if available, slower or network-backed workspaces | Document actual eligibility timings and any failures; do not promise or infer a performance target |
| Real local Ollama | Use an installed local coding model on a synthetic text file; type, cancel, re-trigger and switch languages | Local inline completions are relevant enough to review, cancellation prevents stale suggestions, and settings follow chosen model/language |
| Accessibility | Navigate Control Center, Command Palette, settings and Diagnostics using only keyboard and, if available, a screen reader | Labels are understandable, actions reachable and focus behaves sensibly |
| Upgrade from stable | In a second disposable profile, install published v1.2.0 stable, set synthetic model/language/exclusion preferences, then install v1.2.4 preview | Version becomes 1.2.4, preview channel is visible and synthetic settings remain unchanged |
| Upgrade from preview | Repeat with published v1.2.3 preview as the initial version | Version becomes 1.2.4 and synthetic settings remain unchanged |

## Recording evidence

For each OS, classify the result as **PASS**, **FAIL**, **NOT RUN**, or **BLOCKED** with the VS Code/OS/model versions and reproducible anonymized steps. For measured durations, use small aggregates only; do not record the workspace path or actual source text. When a test fails, open a targeted issue with its sanitized reproduction and link it to [release tracker #54](https://github.com/sanskarIN/LineLoom/issues/54).

## What CI has already checked

The owner-authorized publisher verifies TypeScript/lint/unit/site/bundle checks, real Linux VS Code editor-host tests with a mocked local inference server, dependency audit, actual preview-channel VSIX integrity and SHA-256, isolated CLI installation and checksum-pinned upgrades from published v1.2.0 stable and v1.2.3 preview archives. **These are automated results, not physical Windows/macOS/Linux editor, real Ollama, storage latency, or screen-reader acceptance.**

The stable GitHub release remains **v1.2.0**; this checklist does not authorize any VS Code Marketplace or Open VSX publication.
