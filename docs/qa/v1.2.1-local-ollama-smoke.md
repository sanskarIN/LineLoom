# v1.2.1 real-Ollama and desktop acceptance checklist

**Status: manual verification required.** Automated mock tests and candidate VSIX packaging alone do not verify the real-model/editor experience. Record platform-specific evidence before recommending a stable release. Do not upload private source, prompts, or model output.

## 1. Safe, opt-in local-model smoke test

This command makes requests **only after** the tester supplies `--run` and an installed model name. It permits plain HTTP loopback origins (`127.0.0.1`, `localhost`, `[::1]`) and rejects paths, credentials, HTTPS/remote addresses and redirects. It never scans workspace files, downloads models or prints generated code. It sends only this fixed, synthetic public Python fixture:

```python
def lineloom_public_example_sum(a: int, b: int) -> int:
    return
```

The code is intentionally incomplete to exercise generation. Start Ollama locally and confirm the selected model is already installed:

```shell
ollama list
npm ci
npm run test:qa
npm run qa:ollama -- --run --model qwen2.5-coder:1.5b
```

Replace the model name with one listed by `ollama list`. For a nonstandard **local** port, pass `--endpoint http://127.0.0.1:PORT`. There is no remote-endpoint option.

A successful run reports a small JSON summary with `status: "pass"`, `mode: "local-only"`, platform/architecture, character count and elapsed milliseconds. The text of the completion is never written to the console or to disk by the script. A failed request exits nonzero; errors are deliberately redacted. Note model, host OS, CPU/GPU, Ollama version, and cold/warm timing separately in the tester's local QA report.

**Coverage limit:** this test proves local Ollama model discovery and one synthetic HTTP generation, not VS Code inline acceptance, cancellation timing, screen-reader behavior, or upgrade compatibility.

## Automated privacy regression boundary

The Linux mocked VS Code extension-host suite now opens public synthetic fixtures at excluded credential, Terraform and direnv paths and asserts that calling the real inline-completion provider never dispatches `/api/generate`. It also checks ignored `.gitignore` and `.lineloomignore` paths. This validates the current provider/privacy wiring without contacting a real Ollama installation; it **does not** substitute for real-model or desktop privacy acceptance.

## 2. Physical VS Code editor acceptance (repeat on Windows/macOS/Linux)

- [ ] Install the v1.2.1 candidate VSIX in a **test** VS Code profile. Keep the current stable extension install intact for comparison.
- [ ] Use a disposable, trusted local workspace containing only public example code. Do not use employer/private repositories or secret-bearing files.
- [ ] Open the Control Center through the Activity Bar; confirm current editor language, enabled state, model choice and connection guidance.
- [ ] Confirm a manual inline suggestion can be requested and accepted using keyboard-only interaction; confirm normal typing and IntelliSense still work.
- [ ] Invoke **LineLoom: Stop Current Generation** during a slow real-model response, then verify no stale ghost text is offered. Trigger another request and verify recovery.
- [ ] Pause Automatic Suggestions; confirm manual completion still works and the preference is retained on restart.
- [ ] Test an unavailable local server, an unknown model and an unsupported editor language; confirm useful feedback without revealing prompts or source.
- [ ] Test a temporary file with a sensitive name (for example `.env` or `example.tfvars`) and a protected directory; verify no model call is sent. Use synthetic placeholder text only.
- [ ] Verify Activity Bar navigation, refresh, command labels, high-contrast theme, keyboard focus and screen-reader announcements in the actual desktop app.
- [ ] Verify real cancellation with both queued typing/debounce and in-flight requests. Note whether response fragments appear after stop.

## 3. Upgrade, privacy, and evidence

- [ ] Check v1.2.0 stable -> v1.2.1 candidate on an isolated profile. Retain preferred model, excluded paths, language overrides, enabled state and automatic-trigger choice.
- [ ] Test a separate v1.1.1 preview -> v1.2.1 candidate upgrade when practical; do not overwrite a production profile.
- [ ] If using remote inference, separately exercise the extension's explicit HTTPS consent on an authorized test server. **The CLI smoke test must not support remote origins.**
- [ ] Record VS Code version, OS, Ollama version, model tag, CPU/GPU, observations, failures and repeatable reproduction steps. Do not record private snippets, raw remote errors, tokens or generated confidential material.
- [ ] Verify candidate VSIX SHA-256 and stable-channel metadata; this candidate artifact is not a GitHub stable Release.
- [ ] Keep [issue #31](https://github.com/sanskarIN/LineLoom/issues/31) open until applicable manual tests actually pass. Marketplace/Open VSX publication requires separate authorization and verification.

## Automated tests

`npm run test:qa` runs mocked HTTP/CLI-safety tests only. `npm run check` includes these mocked safety tests but **does not** call a real Ollama server. CI must remain deterministic, private and independent of local model installations.
