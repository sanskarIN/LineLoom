# LineLoom v1.3.1 — proposed maintenance plan

**Status: maintenance features under development; v1.3.1 is NOT published.** Last verified GitHub stable: [v1.3.0](https://github.com/sanskarIN/LineLoom/releases/tag/v1.3.0) (2026-10-25). This document is a proposal, not release authorization. Public registry versions and the optional npm CLI are independent.

## Goal and boundaries

Make the existing local-first completion flow more trustworthy and usable without changing its privacy contract, default endpoint, supported languages or model-provider architecture. Prefer a narrowly scoped patch release over adding more context sources. No automatic workspace indexing, telemetry, unattended downloads, cloud account, background model requests or new permission by default.

### P0 — acceptance and correctness before publication

1. **Manual acceptance debt** — run and record sanitized evidence for [v1.3.0 acceptance](../qa/v1.3.0-manual-acceptance.md), [selected-context follow-up #66](https://github.com/sanskarIN/LineLoom/issues/66) and any surviving relevant checks in [#60](https://github.com/sanskarIN/LineLoom/issues/60). Do not infer manual passes from Linux mocked extension-host CI.
2. **Security** — reassess [packager advisory #79](https://github.com/sanskarIN/LineLoom/issues/79) and the four documented moderate dev-tool transitive audit findings. Reproduce the full high-severity and production moderate-severity audits with a locked install. Confirm an upstream-compatible resolution before changing the pinned VSIX packaging chain; separately test any publisher-authentication change without disclosing credentials.
3. **Completion integrity** — include merged [Unicode formatting hardening PR #99](https://github.com/sanskarIN/LineLoom/pull/99); assess whether additional model outputs should be declined rather than silently edited. Record tests for Python indentation, Rust/TypeScript snippets, CRLF and valid multilingual identifiers.
4. **Privacy and cancellation** — test late settings changes, deletion or edits of selected files, active-editor changes, ignore-policy rewrites, consent revocation and stalled Ollama responses. Reject stale results; do not cache paths or source outside the current process.
5. **Release truthfulness** — verify the actual GitHub release and checksum, compare official marketplace versions independently, and maintain a clear source vs published-artifact status.

### P1 — small fixes if regression-safe

- Improve actionable error wording for unavailable Ollama models, invalid endpoints, blocked privacy policies and manually cancelled requests **without showing paths or prompt bodies**.
- Clarify sidebar selection counts, current inference state, request cancellation and which privacy information is provisional. No automatic connection attempt from rendering the tree.
- Add focused, deterministic integration/regression tests for the highest-frequency editor cases (cursor moves, multi-cursor, native IntelliSense, and mid-token suppression). Avoid UI feature creep in a patch.

### In-progress sidebar improvement (source candidate; not shipped)

- One deterministic **Next:** recommendation in the native Control Center, based on VS Code language/scheme, current configuration, workspace trust and the engine's existing local state.
- Previously registered commands remain the only click targets. The recommendation does **not** call Ollama, inspect source or alter remote approval without a click; it never treats the provisional editor status as a passed file privacy check.
- Empty vs selected session-only related-file context is visibly differentiated without filenames.
- Pure unit tests and Linux VS Code extension-host accessibility checks accompany the source change. Real screen-reader and physical desktop acceptance are still **NOT VERIFIED**. A green CI run is not release approval.

### Explicitly deferred

- New language identifiers or providers, automatic reference discovery, indexing, repository embeddings, multi-file modification, inline chat, or hosted inference.
- CLI v0.2.0/0.3.0 and any npm registry publication: tracked independently by [CLI PR #92](https://github.com/sanskarIN/LineLoom/pull/92) and [package guide](../packages.md).
- Marketplace/Open VSX v1.3.1 publication until separately approved; GitHub stable publication is not authorization for those registries.

## Proposed PR sequence

| Step | Proposed PR | Exit condition |
| --- | --- | --- |
| 1 | Acceptance evidence and issues triage | Issues distinguish *passed*, *not run* and *intentionally deferred* with reasons and dated sanitized evidence |
| 2 | Small completion/editor and sidebar bug fixes | New unit + Linux VS Code host regression for each fixed behavior |
| 3 | Security and publishing dependency maintenance | Compatible dependency graph, clean locked install, audited CI, VSIX pack and upgrade; publisher credentials checked separately |
| 4 | Release candidate documentation and build | Clean install/upgrade, complete CHANGELOG, checked archive identity and SHA-256; real-model/physical OS gaps declared |
| 5 | Explicit owner review/authorization | Only the separately authorized version-specific workflow may publish a GitHub stable VSIX |

## Reproducible measurement and QA matrix

Capture only aggregate counts, editor/OS/model versions and sanitized test outcomes. Never attach prompts, proprietary code, remote endpoint secrets or absolute private filenames.

| Scenario | Method | Desired evidence |
| --- | --- | --- |
| Single file baseline | Same fixed synthetic fixtures with related context OFF | Correctness examples, acceptance/rejection counts, p50/p95 end-to-end latency |
| Related context | Same fixtures, ON with explicit 1–2 tiny allowed reference files | Quality delta and latency delta vs baseline; deny/no-read checks |
| Cancellation | Delay mock responses, edit/switch editor, change policy and revoke consent | No late ghost text; no post-revocation selected context |
| Resource usage | Local Ollama CPU/GPU on available desktop configurations | Approximate peak memory and latency distribution; document machine/model |
| Accessibility | Keyboard-only, high-contrast and screen reader on physical platforms | Exact path through picker and modal, focus behavior, success/failure |
| Installation | Fresh installation and profile upgrade from published v1.2.0/v1.3.0 | Package identity, extension startup, preserved synthetic preferences |

No numeric quality/performance target is asserted before a baseline is measured. Failure to complete an item requires explicit deferral in the release notes, not an invented PASS.

## Release acceptance

- [ ] `npm ci`, `npm run check`, package tests where changed, cross-platform CI and Linux VS Code host passed.
- [ ] `npm audit --audit-level=high` and `npm audit --omit=dev --audit-level=moderate` passed against the committed lockfile.
- [ ] Exact stable-channel VSIX identity/version, clean CLI install, pinned upgrade checks and SHA-256 verified.
- [ ] Manual local Ollama quality and accessibility/desktop status documented with dated evidence or explicit owner-reviewed deferral.
- [ ] README, website, package guide and release notes do not misstate which artifacts were published.
- [ ] Owner explicitly authorizes the intended channel(s). Never retag or silently republish v1.3.0.
