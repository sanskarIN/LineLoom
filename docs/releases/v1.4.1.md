# LineLoom v1.4.1 — LineLoom Code Research & Privacy Preview

**Release state: [GitHub v1.4.1 pre-release published and verified](https://github.com/sanskarIN/LineLoom/releases/tag/v1.4.1) on 2026-10-26.** The [version-specific owner-authorized publisher](https://github.com/sanskarIN/LineLoom/actions/runs/40265555223) completed successfully; genuine preview VSIX and SHA-256 are public. It is **not a stable release**. The latest verified stable remains [v1.3.0](https://github.com/sanskarIN/LineLoom/releases/tag/v1.3.0). No registry or publisher migration.

## New since GitHub preview v1.4.0

- **Explicit sanitized support report — [PR #126](https://github.com/sanskarIN/LineLoom/pull/126):** user-triggered Copy Sanitized Support Summary through native sidebar, Quick Actions and Command Palette. Allowlisted session counts and last-check states only, no source, file paths, prompt, endpoint URL, model tags or private document identities. Optional aggregate timing only after diagnostics opt-in; the user's clipboard is visible to other local apps and should be reviewed before sharing.
- **Editor-scoped readiness correction — [PR #126](https://github.com/sanskarIN/LineLoom/pull/126):** switching, changing or closing editors revokes the prior editor's manual file privacy and active-model check snapshots and rejects old asynchronous outcomes.
- **Cancellation of obsolete manual model discovery — [PR #127](https://github.com/sanskarIN/LineLoom/pull/127):** superseding /api/tags checks, editor/configuration changes and trust invalidation abort stale user-invoked model-list network work. No background monitoring or automatic model download.
- **LineLoom Code synthetic comparison — [PR #129](https://github.com/sanskarIN/LineLoom/pull/129):** offline comparison of exactly two bounded JSON reports using deterministic fixture-content SHA-256, the same prompt mode and repetition count. Source-free per-language/category exact-match and latency deltas. No real local model benchmark was run.
- **Dataset governance preflight — [PR #130](https://github.com/sanskarIN/LineLoom/pull/130):** opt-in offline manifest audit for human-declared rights, provenance-revision syntax, train/validation/test split isolation, approximate duplicates and public synthetic evaluation contamination, and obvious secret/PII patterns. A successful mechanical screening **does not authorize training** or establish legal permission.
- **Synthetic benchmark protocol v2 — [PR #131](https://github.com/sanskarIN/LineLoom/pull/131):** aggregate conservative response-format signals for empty output, markdown, chat preamble, special tokens, hidden Unicode and echoed prefix/suffix. Strict separation of v1/v2 comparison protocols. **Not** compile correctness or semantic quality.

The extension remains MIT-licensed, local-first and tied to user-configured Ollama by default. Related-file context remains off by default and requires explicit selection. Workspace trust, sensitive-file filtering and separate remote HTTPS approval continue to apply. The extension ID remains **`SanskarCodes.lineloom`**; publisher rename or registry migration is **not authorized**.

## Verification, quality and release limitations

All feature PRs above passed their own Windows/macOS/Linux checks, mocked Linux VS Code extension-host, security audit, and independent VSIX candidate packaging verification. **The [v1.4.1 publishing workflow passed](https://github.com/sanskarIN/LineLoom/actions/runs/40265555223)**, including a genuine VS Code pre-release marker, SHA-256 validation, a clean install, and isolated pinned v1.3.0 stable-to-v1.4.1 upgrade. It rejected duplicate tags and verified exact public asset names.

**Manual QA outstanding — NOT RUN:** real Ollama quality/latency results, dedicated trained LineLoom Code weights, reviewed/approved training corpus and base checkpoint, physical Windows/macOS/Linux VS Code keyboard and screen-reader behavior, privacy/consent tests on actual user-controlled files, and real remote endpoint approval tests. Automated mocks do not substitute for that evidence.

**Four moderate development-only transitive dependency advisories** were documented during previous preview preparation in [issue #79](https://github.com/sanskarIN/LineLoom/issues/79). A passing high-severity audit does not imply a zero-advisory tree. The publisher must still pass high/critical complete-toolchain and moderate-or-higher production-only dependency checks; assess dev-only advisories separately.
