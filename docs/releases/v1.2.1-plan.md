# LineLoom v1.2.1 — Released Maintenance Pre-release (Historical Plan)

**Status:** [v1.2.1 GitHub pre-release published 2026-10-22](https://github.com/sanskarIN/LineLoom/releases/tag/v1.2.1), using the real VS Code preview manifest marker and two verified assets. This plan remains a record of the candidate's work and outstanding manual QA.
Latest public [GitHub stable is v1.2.0](https://github.com/sanskarIN/LineLoom/releases/tag/v1.2.0).
Do not claim a **v1.2.1 stable-channel, Marketplace or Open VSX release**; this version is **GitHub pre-release only**.

## Scope

The first maintenance increment makes cancellation an explicit user choice:

- **LineLoom: Stop Current Generation** is available in VS Code's Command
  Palette, the LineLoom native Control Center and status-bar Quick Actions.
- The stop action invalidates a queued request ID, aborts any in-progress
  Ollama HTTP request and clears stale memory-only suggestion results. A late
  response must not be inserted.
- Stop does **not** change `lineloom.enabled` or
  `lineloom.autoTrigger`; future automatic and manual suggestions remain
  available. Pause Automatic Suggestions remains a separate persistent
  preference.
- Additional non-overridable sensitive-path checks protect Terraform state/variables, environment secrets, key stores and cloud credential directories, with Windows-path regression coverage (merged [PR #32](https://github.com/sanskarIN/LineLoom/pull/32)).
- Added an optional local-only real Ollama smoke tool using a public synthetic fixture and minimal metadata output. Run `npm run qa:ollama -- --run --model <installed-tag>` to verify a real installed model without accessing workspace code. Automated mocked safety tests run under `npm run check`; the real smoke command is **never called automatically**. See [manual acceptance checklist](../qa/v1.2.1-local-ollama-smoke.md).
- Added mocked VS Code editor-host regression tests that invoke the actual inline provider on synthetic protected paths and verify no Ollama generation request is dispatched; this is automated evidence, not real-model acceptance.
- Privacy hardening: non-overridable sensitive-path rules now inspect **every ancestor segment** (including `credentials/`, `secrets/`, `.env.local/` and `.dev.vars.preview/`), not just a file's basename. Mocked VS Code editor-host tests open these synthetic protected files and prove they cannot reach Ollama. This does not implement content-level secret scanning.
- Pending patch improvement: ignore-file creation, edits and deletion invalidate outstanding asynchronous privacy scans, stop queued/in-flight generation, and prevent stale ignore reads from repopulating the cache. The mocked editor-host test checks policy invalidation and verifies that a newly excluded synthetic file cannot trigger Ollama or reuse an old suggestion. Real filesystem watcher timing remains subject to editor/platform acceptance.
- Pure command and sidebar tests, manifest verification, and Linux mocked
  Ollama editor-host integration cover the new behavior. Two cancellation
  scenarios are checked: pending debounce (no network send), and in-flight
  response (no stale completion).
- Add a Linux CI upgrade smoke that verifies the downloaded **published v1.2.0 stable VSIX** against its pinned GitHub release SHA-256, then installs v1.2.0 and the v1.2.1 candidate sequentially using the same **disposable** VS Code extensions directory/user profile. Assert that the CLI lists only v1.2.1 afterward and that synthetic model, language, automatic-mode, exclusions and diagnostic settings remain byte-for-byte identical. This covers isolated CLI packaging/upgrade mechanics only; **physical desktop and interactive settings behavior remain unverified**.
- Bump package and lockfile to `1.2.1`. Automated CI produces
  `lineloom-v1.2.1-patch-candidate` containing a stable-channel test VSIX and
  SHA-256. The artifact is **not** a versioned GitHub Release.

  installed Ollama model; test keyboard and screen-reader command access. A dedicated

  real-hardware results still need to be collected.

- [ ] Check v1.2.0-to-v1.2.1 settings upgrade and desktop behavior.
