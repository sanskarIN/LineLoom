# LineLoom v0.7.1 — Typed Continuation Edit Safety Preview

**GitHub pre-release · Apache-2.0 · VS Code and Ollama · not stable**

This maintenance release tightens the typed suggestion continuation feature introduced in v0.7.0. LineLoom now checks what VS Code actually changed before offering leftover ghost text from a previously generated completion.

## Changes since v0.7.0

- **Validate real editor edits:** reuse is permitted only when an edit contains exactly one insertion at the original cursor, the inserted text is the beginning of the previous suggestion and its length is within 1–32 characters.
- **Reject stale suggestions:** replacements, deletions, edits elsewhere, multi-part edits, unexpected typed characters, skipped document versions and complete consumption of the previous suggestion clear the continuation cache.
- **Retain privacy checks:** after edit validation, the trusted-workspace gate, root/nested ignore files, current editor, exact code prefix/suffix hashes and model/endpoint settings must still match. The existing 12-second, single-candidate memory-only limit is unchanged.
- **Regression tests:** added unit tests for invalid edit shapes and updated the VS Code extension-host suite to use genuine document-change events. Synthetic editor tests confirm unrelated changes cause a new **mock Ollama** call instead of reusing an obsolete completion.
- **Maintenance documentation:** updated README, changelog, architecture, development and troubleshooting guidance.

LineLoom retains the v0.7.0 functionality: Ollama-first autocomplete in nine editor language modes, Quick Actions, manual-only mode, bounded source context, sensitive-file exclusions, HTTPS approval and HTTP redirect rejection. Go, Java, C and C++ remain experimental. No new accounts, cloud inference providers, downloads or telemetry.

## Installation

1. Install a VS Code version compatible with `^1.96.0` and start Ollama with an independently installed coding model.
2. Download `LineLoom-0.7.1.vsix` from this release's Assets.
3. Use **Extensions → … → Install from VSIX** in VS Code, or `code --install-extension LineLoom-0.7.1.vsix`.
4. Open a trusted workspace, click the **LineLoom** status-bar entry, check your Ollama connection and choose a model.
5. If you type only the beginning of a generated suggestion at its cursor, LineLoom can reuse the remaining text. Edits elsewhere intentionally trigger normal generation.
6. Where available, verify the asset with `sha256sum -c LineLoom-0.7.1.sha256`.

## Validation and limitations

The publication pipeline requires `npm ci`, TypeScript checks, lint, unit tests, bundled extension build, a real VS Code extension-host integration test with **mocked Ollama**, dependency audit, VSIX ZIP integrity inspection and a SHA-256 checksum. CI also checks Windows, macOS and Ubuntu.

**Not independently verified:** real coding-model output quality in nine languages, actual acceptance and latency of ghost text, CPU/GPU performance, fully offline setup and manual VSIX installation on each desktop OS. LineLoom is not a content-based secret scanner or repository index; review suggested code and approved inference endpoints.

This is a GitHub **pre-release**, not stable v1.0.0, and it has not been asserted as published on VS Code Marketplace or Open VSX.
