# LineLoom v1.2.0 stable release plan

**Status: STABLE-CHANNEL BUILD CANDIDATE — NOT RELEASED.** The preceding
v1.1.1 was published as an opt-in GitHub pre-release. Existing v1.0.0 stable packages on VS Code Marketplace and
Open VSX remain supported until they are explicitly updated and verified.

The CI build candidate is downloadable from GitHub Actions artifacts, but
its tests do **not** replace required real-world acceptance. See the
[manual matrix](../qa/v1.2.0-acceptance.md).

## Primary stable target

Promote the native LineLoom Activity Bar Control Center from preview to
a dependable stable experience, while maintaining strict local-first privacy.

The stable candidate should preserve:

- Inline ghost-text completions and user-initiated manual fallback
- Per-language Ollama model routing for the nine current language IDs
- A responsive sidebar showing model, language, privacy/connection categories,
  active-editor eligibility and aggregate session activity
- File-only editor scheme guards, workspace trust and ignore/sensitive-file
  exclusions, with explicit origin approval for optional remote HTTPS
- Cancellation and stale-response protection; no telemetry, model auto-download,
  automatic remote access or unapproved cross-file reads

**Potential enhancements** (not guaranteed): additional languages (C# / Dart),
model failure recovery UX, keyboard usability improvements, model-quality
regression fixtures and latency tuning. New language support will be included
only if backed by extension-host coverage and realistic quality checks.

## Automated release blockers

- [ ] Set manifest + lockfile + pinned tests to `1.2.0`
- [ ] TypeScript, ESLint, unit tests and static Pages tests pass
- [ ] Windows/macOS/Linux CI build and checks pass
- [ ] Linux VS Code extension-host integration with mocked Ollama passes
- [ ] Dependency high-severity audit passes
- [ ] Build **stable** VSIX (without `--pre-release`); verify archive entries,
  publisher, icon, package identity and checksum
- [ ] Install packaged VSIX using an isolated VS Code CLI
- [ ] Confirm stable tag does not already exist; never alter old releases

## Manual release blockers (NOT YET VERIFIED)

- [ ] Install and upgrade from stable v1.0.0 and pre-release v1.1.1 in VS Code
- [ ] Test supported workflows on real Windows, macOS and Linux desktops
- [ ] Confirm real Ollama model download performed explicitly by tester,
  connection, model switching, ghost-text output and acceptance
- [ ] Validate ignored, sensitive, unsupported-scheme and restricted editors
  cannot cause accidental source disclosure
- [ ] Validate remote HTTPS opt-in, consent, disabled-by-default and cancellation
- [ ] Check keyboard-only sidebar usage, high contrast and screen-reader labels
- [ ] Record cold/warm completion latency on CPU and GPU with real hardware/model
  metadata, fixture, timings and any observed output-quality defects
- [ ] Address release-blocking regressions and record evidence/issues

## Release/distribution order

1. Review automated + manual evidence and resolve high-severity failures.
2. Freeze and tag **v1.2.0 stable** after all blockers pass. Build a regular
   stable-channel `LineLoom-1.2.0.vsix` plus SHA-256, keeping pre-releases intact.
3. Publish GitHub stable release with verified downloadable assets.
4. Independently publish/update `SanskarCodes.lineloom` on Visual Studio
   Marketplace and Open VSX, using authorized publisher credentials and official
   mechanisms; do not put any credentials in the repository.
5. Inspect both public registry pages for `1.2.0` before advertising
   marketplace availability. Update website/README, release notes and support docs.
6. Monitor user-reported upgrade, privacy and completion issues.

GitHub Releases do **not** publish to the external registries automatically.
Automated CI and mocked Ollama are not proof of real-model quality or physical
editor acceptance. [Tracked release gates](https://github.com/sanskarIN/LineLoom/issues/21).
