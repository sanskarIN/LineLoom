# LineLoom v1.4.5 — publisher migration preparation (plan only)

**Status: PLANNED / NOT PUBLISHED (2026-11-18).** The latest verified public GitHub pre-release is [v1.4.4](https://github.com/sanskarIN/LineLoom/releases/tag/v1.4.4), and the GitHub stable release is v1.3.0. This document is a release **plan**, not a tag, downloadable VSIX, registry upload, or authorization to publish.

## Purpose and non-goals

Use **v1.4.5 as a pre-release candidate** to document and test migration from `SanskarCodes.lineloom` to the desired permanent `Sanskar.lineloom` publisher identity. Record the Microsoft support decision and prepare the user-facing process **before** v1.5.0 Stable. A dual-publisher GitHub preview is not an automatic account transfer.

- Maintain the existing `SanskarCodes.lineloom` Marketplace and Open VSX listings while any migration is pending.
- Preserve the local-first privacy policy, explicit selected-file context boundaries, user settings safety, no automatic telemetry, and no silent remote inference.
- Do not assume that Microsoft can reassign the original listing or transfer ratings, download statistics, subscriptions, installations, extension storage, or update continuity.
- Do not change the tracked extension publisher, announce a replacement listing, upload to registries, train/download model weights, or run a release solely because this plan is merged.

**Support decision branches:**

1. **Microsoft confirms official reassignment:** obtain the exact supported procedure, which public ID changes, impact on existing subscribers/ratings and old listing, and how to verify completion. Do not call transfer complete merely because support says it is possible.
2. **Microsoft cannot transfer the exact extension ID:** stop any attempted duplicate-name upload. Ask the owner to approve a distinct compliant extension name/display name and an explicit manual user-migration strategy. Do **not** delete the legacy listing to free its name.
3. **No answer, unclear terms, or partial transfer:** remain in pending state. GitHub migration preview testing can proceed under a separate version authorization, but **v1.5.0 Stable is blocked**.

Microsoft's [publishing guide](https://code.visualstudio.com/api/working-with-extensions/publishing-extension) states Marketplace extension names/display names must be unique and removal permanently reserves an extension name.

- [ ] Choose the exact reviewed `main` commit, update the version only as part of separately authorized candidate preparation, and record an immutable changelog.
- [ ] Fix/assess the active [full dependency security audit blocker #297](https://github.com/sanskarIN/LineLoom/issues/297); never bypass the gate with an unreviewed forced dependency downgrade.
- [ ] Typecheck, lint, unit, model-evaluator and source-tree checks; mocked VS Code extension-host integration and Windows/macOS/Linux CI.
- [ ] Inspect the `SanskarCodes` and `Sanskar` **pre-release** VSIX manifests; verify exact version/channel, SHA-256 hashes, full shipped-file parity, and clean installation in isolated editor profiles.
- [ ] Validate deliberate old-ID uninstall/new-ID install with synthetic settings and fresh remote-endpoint consent. Check overlapping command/configuration IDs never run together. Keep a tested rollback to the existing stable listing.
- [ ] Verify that chosen related-file access remains default-off, bounded and fail-closed; include cancellation, file replacement, ignore rules, trust and settings revocation tests.
- [ ] Record physical VS Code Windows/macOS/Linux, keyboard/accessibility and real local Ollama tests as PASS, FAIL, DEFERRED or NOT RUN using [release evidence rules](../qa/release-evidence.md); do not turn CI success into a manual pass.
- [ ] Explain exactly which GitHub pre-release assets exist, and explicitly state that **neither external registry nor the npm CLI was migrated or updated**.
- [ ] Obtain explicit owner approval for **v1.4.5 GitHub pre-release publication only**, if and when all applicable gates pass.

**Exit state:** a fully documented, tested GitHub-only migration preview is eligible for separately approved publication. It is **not** a stable release and does **not** satisfy v1.5.0 publisher-confirmation requirements.
