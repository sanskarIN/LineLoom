# LineLoom v0.8.1 — Unicode & Response-State Safety Preview

**GitHub pre-release · MIT License · local-first VS Code autocomplete using Ollama**

## Changes since v0.8.0

- **Better Unicode editing:** automatic completion no longer interrupts identifiers at combining marks, connector punctuation and zero-width joiners, in addition to existing letter/digit handling. **LineLoom: Trigger Completion** still works inside identifiers and `lineloom.suppressMidTokenAuto` allows opting out.
- **Safer delayed responses:** before displaying a generated completion, LineLoom rechecks that the extension is enabled, the language is allowed, the configured model and endpoint still match, relevant inference parameters have not changed, and any remote endpoint remains approved. This protects against late configuration notifications while inference is completing.
- **Correct debounce regression test:** the editor suite tests the cancellation of an **automatic** request during its configured delay rather than using the manual trigger, which correctly bypasses typing debounce.
- **Expanded unit tests:** model/endpoint/settings mismatch, language disablement, manual vs automatic policies and Unicode identifier boundaries.
- **No feature regressions intended:** nine registered language modes (Python, JavaScript/JSX, TypeScript/TSX, Rust, Kotlin, Go, Java, C, C++), short-lived typed continuation cache, Quick Actions, ignored-file privacy, HTTPS origin approval, redirect rejection and no telemetry remain.

## Installation / upgrade

1. Install VS Code compatible with `^1.96.0` and install/start Ollama plus a coding model separately.
2. Download `LineLoom-0.8.1.vsix` from this GitHub release's Assets.
3. Choose **Extensions → … → Install from VSIX** or run `code --install-extension LineLoom-0.8.1.vsix`.
4. Open a trusted source workspace and use **LineLoom: Quick Actions** to select and verify your installed model.
5. Optionally verify `LineLoom-0.8.1.sha256` via `sha256sum -c LineLoom-0.8.1.sha256` on a compatible shell.

## Verification and limitations

The publication workflow checks locked npm installation, strict TypeScript, lint, unit tests, bundled extension, VS Code extension-host integration with **mocked Ollama**, dependency security audit, VSIX ZIP archive integrity and SHA-256 checksum. CI separately tests Windows, macOS and Ubuntu.

**Still unverified:** real installed Ollama model suggestions across nine languages, real user ghost-text acceptance, latency and CPU/GPU performance on representative hardware, fully offline user setup and fresh manual VSIX testing on all three operating systems. The Unicode gate is a conservative character heuristic and cannot guarantee language-specific syntax accuracy. Changing settings while inference is pending can prevent a suggestion being shown, but cannot recall source already delivered to an approved endpoint.

This is a GitHub **pre-release**, not stable v1.0.0 or a claimed VS Code Marketplace/Open VSX publication.
