# LineLoom v1.2.3 — Live Ignore-Policy Safety (Development Only)

**Status: in development, not tagged or published.** Latest GitHub stable is v1.2.0; v1.2.2 is the latest GitHub preview.

## Safety improvement

- Real VS Code editor-host tests showed nested `.lineloomignore` creation could be missed by workspace-level filesystem watchers; a pre-existing cached allow decision persisted beyond eight seconds.
- v1.2.3 now validates the existence, type, size and modification time of every applicable `.gitignore` and `.lineloomignore` source before reusing a cached permission decision, including policy files previously absent.
- If a policy source changed during asynchronous scanning, completion fails closed. Policy caches are still short-lived, bounded, in memory, and cleared on watcher events.
- As a follow-up hardening step, cached policy snapshots now also include an in-memory SHA-256 digest of each existing ignore file's raw bytes. Fresh policy validation compares both metadata and the content digest, so size/timestamp-preserving edits cannot reuse stale cached permissions. Missing sources remain checked for creation. This increases filesystem read and hashing overhead; benchmark deep workspaces and do not claim atomic protection from races or retraction of already transmitted source. Synthetic unit coverage and real Linux editor-host regression include the same-size/same-mtime rewrite case.
