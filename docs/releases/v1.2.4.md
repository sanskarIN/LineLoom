# LineLoom v1.2.4 — Privacy Eligibility Diagnostics GitHub Pre-release

**GitHub-only pre-release, contingent on a separately owner-authorized publishing commit.** This release uses VS Code's genuine **pre-release channel** metadata. It is not a stable release or an automatic Microsoft Marketplace/Open VSX update.

## What's new

- **Opt-in privacy timing diagnostics:** `lineloom.performanceDiagnostics` (disabled by default) records only aggregate time taken by LineLoom's source eligibility checks.
- **Useful timing statistics:** allow/deny counts; last, session-average and session-max eligibility latency; and a bounded rolling 64-sample p95 value, displayed in LineLoom's native diagnostics command.
- **Privacy by design:** no file paths, source code, prompts, ignore rules, model responses or per-document identifiers are added to timing storage. All data is kept in-memory for the session, with no additional model/server requests.
- **Instant opt-out handling:** when performance diagnostics are disabled, the active extension clears accumulated timing statistics; late asynchronous policy checks do not repopulate data after opting out.
- **Version and test alignment:** manifest and lockfile are 1.2.4, with unit regressions and real Linux VS Code editor-host integration for opt-in, aggregation, and disabled recording.
- **Improved upgrade confidence:** the publisher verifies the published v1.2.0 stable and v1.2.3 preview VSIX archives against individually pinned SHA-256 digests; disposable VS Code profiles must upgrade to v1.2.4 with synthetic model/language/privacy/automatic-completion preferences preserved byte-for-byte.

Eligibility check latency is **not** model inference latency, end-to-end suggestion quality or an independently measured workstation benchmark. The rolling p95 is a diagnostic estimate from at most 64 recent samples.

## Release files

- `LineLoom-1.2.4.vsix` — the genuine VS Code **pre-release** extension for `SanskarCodes.lineloom`.
- `LineLoom-1.2.4.sha256` — checksum for that exact archive.

In **VS Code**, open Extensions → … → Install from VSIX… and choose the downloaded file. Use a disposable VS Code profile to test preview versions. Do not use the full Visual Studio IDE VSIX Installer.

## Manual QA outstanding

Physical Windows/macOS/Linux editor installs and upgrades; real Ollama latency and suggestion quality; real filesystem watcher timing; performance on slow/network filesystems; and keyboard/screen-reader accessibility **have not** been independently verified. Automated VS Code host tests use synthetic files and a mocked local server, not real private code. Evaluate preview versions with disposable, non-sensitive projects.
